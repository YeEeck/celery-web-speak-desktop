# 浮层窗口尺寸由页面测量上报，壳层不再预测行高（协议 3）

协议 2 起浮层窗口几何由壳层按参与者行数预测：`height = N × 36 × scale`，而"行高基准 36px（含行距）"被定为两仓共享契约。该契约要求壳层复制 Web 侧布局知识（行高与行间隙），两份实现各自演化且无法在 CI 中对账——浮层页面引入 6px 行间隙后契约即失效，窗口高度系统性偏矮，最后一行底部被切掉 (N−1)×6px。

改为测量上报（measure-and-report）：协议 3 起，浮层页面用 ResizeObserver 测量自身内容尺寸（含 CSS zoom 缩放），经浮层窗口 IPC 通道 `voice-overlay:report-content-size` 上报 `{width, height}`；壳层不再按行数计算高度，只按浮层配置计算窗口位置（中心点百分比）并应用上报尺寸。行高契约删除——行高与行间隙彻底成为浮层页面的纯 UI 选择，字体、DPI 或未来布局改版都不会再错位。

壳层对上报尺寸做合理性钳制（宽高 ≥ 1 且不超过工作区）；窗口显示门控在"页面就绪且已收到首个尺寸上报"，避免首帧以错误尺寸闪现。`scalePercent` 变为纯样式配置（页面 CSS zoom），壳层不再消费。

协议升级为 3：协商回退到协议 2 及以下的旧壳时，浮层整体禁用（与协议 1 的处理模式一致）；Web 端把可用协议下限提到 3，握手协商回退即视为桥不可用。代价是旧桌面壳 + 新 Web 组合需要升级壳才能恢复浮层，浮层为桌面专属功能、壳有独立发布节奏，可接受。

备选方案：保留预测并修契约（复制知识继续存在，靠纪律维护，无法根治）；全屏透明窗口把 UI 全权交给 Web（架构最简，但常驻全屏透明合成对游戏场景有真实性能代价）。
