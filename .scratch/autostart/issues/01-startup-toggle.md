# 01: 「随系统启动」开关（写入、回显与外部禁用）

**What to build:** Windows 正式包的用户可以在"更多"菜单里看到一个「随系统启动」勾选项。勾选后操作系统侧出现本应用的启动条目，取消勾选后条目消失；重新打开菜单时，勾选状态来自操作系统的真实状态，而不是应用自己的记忆——用户在任务管理器"启动"页禁用或删除条目后，菜单会如实变成未勾选。写入静默失败时，勾选随重新读取的结果弹回未勾选，并留下一条本地日志。开发模式与非 Windows 平台看不到该项，也不能绕过它触发系统写入。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 启动条目模块以可注入后端实现，对外只有"读启用状态 / 设置启用 / 路径核对"三个能力；后端用伪实现即可在非 Windows 上覆盖全部五种状态（不存在、启用、外部禁用、路径漂移、写入抛错）
- [ ] 条目名固定为 `Celery Web Speak`，写入的命令行包含 `--autostart` 参数；启用状态按"名字 + 当前可执行文件路径"判定，不依赖 `openAtLogin`
- [ ] 菜单出现「随系统启动」，位于「自动检查更新」相邻位置，远程模式与配置模式都显示，键盘导航可选中并触发
- [ ] 勾选后重新打开菜单显示已勾选；取消勾选后重新打开显示未勾选；整个过程不需要重启应用
- [ ] 条目被外部删除或被外部禁用后，重新打开菜单显示未勾选
- [ ] 后端写入抛错时，重新打开菜单仍显示未勾选，且日志出现对应事件；不弹出任何对话框
- [ ] 开发模式（未打包）下菜单不出现该项，且即使渲染层伪造该动作，主进程也拒绝
- [ ] 非 Windows 平台下菜单不出现该项
- [ ] 菜单弹出窗口高度随项目数调整，新增项之后最后一项完整可见、底部无空白
- [ ] `config.json` 不出现新字段；切换服务器后该开关的表现不变
